# Cardalyzer

Cardalyzer reads your card data and turns each card's effects into gameplay
in Tabletop Simulator. Write a card's effects in a spreadsheet
(`gold:2; draw:1`) and Cardalyzer parses them, checks them against your game's
rules, and runs them on the table, along with the turn structure around them.

It isn't limited to one genre. The first rules it ships with cover a
deck-builder: starter decks, a market row, drawing, turn cleanup and
reshuffling. Other card games plug in the same way, through a rules module.

It ships with **Ember Guilds**, a small original sample game with placeholder
art, so the repo contains none of anyone else's names or artwork.

## Quick start

You need Python 3 with Pillow (`pip install pillow`). Lua 5.2 is only needed to run the tests.

```sh
python tools/csv2json.py games/sample/cards.csv   # cards.csv -> cards.json
python tools/make_sheets.py games/sample          # placeholder card sheets -> art/ + art.json
python tools/bundle.py games/sample               # -> build/Global.lua
lua tests/run.lua                                 # headless tests with fake TTS globals
```

(`make all` does the same on macOS/Linux.)

Then in Tabletop Simulator:

1. Host the sheet images somewhere TTS can load them, and set `art.baseUrl` in
   `games/sample/rules.lua`. Once this repo is on GitHub the raw URL works:
   `https://raw.githubusercontent.com/<owner>/<repo>/main/games/sample/`.
2. Rebuild, then paste `build/Global.lua` into the Global script (or push it
   with the [TTS Editor](https://marketplace.visualstudio.com/items?itemName=sebaestschjin.tts-editor) VS Code extension) and Save & Play.
3. Press **New Game** (host only). **End Turn** works for the seated active player.

The script places its own scripting zones and moves each seat's hand zone,
so start from an empty table.

## Layout

```
src/
  main.lua           Global entry: onLoad, onSave, button handlers
  engine/
    cards.lua        card library, effect-string parsing
    effects.lua      keyword registry (resources, stats, draw, custom:...)
    state.lua        game state tables (saved with onSave)
    turn.lua         setup, draw/reshuffle, market refill, end-of-turn cleanup
    zones.lua        table layout maths + spawning scripting/hand zones
    board.lua        renders state as TTS objects
    ui.lua           XML status panel and buttons
    game.lua         facade that wires the modules together
games/sample/
  cards.csv          the card spreadsheet (source of truth)
  cards.json         generated by csv2json.py
  rules.lua          everything game-specific
  art/, art.json     generated by make_sheets.py
tools/               csv2json.py, make_sheets.py, bundle.py
tests/               run.lua + fake TTS API
```

### How it works

- **State is the truth.** Every card is an instance with a uid; piles are lists
  of uids (last = top). Physical cards carry their uid in GM Notes.
- **The board is a view.** A pile is redrawn by destroying what it spawned and
  spawning fresh objects, so stray drags can't desync the game. Later
  milestones read player actions (dragging a card into the play zone) as
  input and update state, rather than trusting positions.
- **Reload-safe.** `onSave` stores the whole state, including the GUIDs of
  zones and spawned objects, so loading a save reuses them.

## Card format

One row per card in `cards.csv`:

```csv
id,name,deck,faction,type,cost,copies,effects,ally_effects,scrap_effects,defense,text
apprentice,Apprentice,starter,none,unit,0,8,gold:1,,,,
hireling,Hireling,fixed,none,unit,2,10,gold:2,,might:2,,
war_anvil,War Anvil,market,forge,building,4,1,might:3,,,5,
```

- `deck`: `starter` (copies per player), `market` (shuffled into the market
  deck), or `fixed` (an always-available pile next to the row).
- `effects`, `ally_effects`, `scrap_effects`: `;`-separated `keyword:amount`.
  Keywords are each resource and stat named in the rules (`gold`, `might`,
  `health` in the sample) plus `draw`, `scrap_hand` and `opponent_discard`.
- `custom:name` calls `rules.customEffects.name` for anything unusual.
- `defense` is for persistent card types (bases/buildings).

Bad rows are caught twice: `csv2json.py` checks the format, and the engine
checks every keyword against the rules when the mod loads.

## Making your own game

Copy `games/sample` to `games/<yours>`, edit `cards.csv` and `rules.lua`
(seat colours, resource and stat names, hand sizes, market size, card types,
faction colours, custom effects), then run the three tools with your folder.
No engine code should need to change; if it does, that's an engine bug.
